## 一、两个开关

```python
import config as C
C.configure("cifar100", "resnet18")     # 跑之前调用一次
# 之后 C.CKPT_MAIN / C.NUM_CLASSES / C.MEAN / C.STD / C.RESULT_DIR 全部自动跟着变
```

命令行等价：

```bash
PTQ_DATASET=cifar100 PTQ_ARCH=mobilenetv2 ./run.sh all
```

**支持矩阵**：

| DATASET | 类别数 | mean[0] | std[0] |
|---|---|---|---|
| cifar10 | 10 | 0.4914 | 0.2470 |
| cifar100 | 100 | 0.5071 | 0.2673 |

| ARCH | 参数量 | Conv2d 层 | 其中 depthwise |
|---|---|---|---|
| resnet18 | 11.18 M | 20 | 0 |
| mobilenetv2 | 2.24 M | 52 | **17** |

## 二、⚠️ 两个必须知道的陷阱（都是实测踩的）

### ① 归一化参数必须跟着数据集走

CIFAR-100 的 mean/std 和 CIFAR-10 不同（0.5071/0.2673 vs 0.4914/0.2470）。
**用错会让 FP32 基线本身偏低**，后面所有"掉点"数字都失真——
而且这种错误很难发现，因为它看起来只是"基线差一点"。

### ② CIFAR-10 的数据路径是历史特例，不能挪

CIFAR-10 的数据躺在 `paper-code/data/` **根目录**下（子目录名 `cifar-10-batches-py`
是 torchvision 自己解包决定的），不能改成 `paper-code/data/cifar10/`。
**我第一次改的时候就踩了：改完默认组合直接跑不起来。**

现在 `dataset_dir()` 里对 cifar10 做了特例处理。

### ③ 权重路径：默认组合走历史路径

`cifar10 + resnet18` 的两个权重（`cifar_resnet18_50ep.pth` / `cifar_resnet18.pth`）
**必须继续指向 `paper-code/` 根目录**——它们是 87.16% 的来源，挪了整个平台就废了。

其他新组合才放 `paper-code/ckpts/{dataset}_{arch}_{tag}.pth`。

## 三、改了哪些文件

| 文件 | 改动 |
|---|---|
| `config.py` | 加 `DATASET_SPECS` / `ARCH_SPECS` / `configure()`；所有派生量由开关推导 |
| `src/data.py` | 按 `C.DATASET` 分发 CIFAR10/CIFAR100；新增 `ensure_dataset()` |
| `src/model.py` | 新增 `build_fp32()` 按 `C.ARCH` 构造；`load_fp32()` 缺权重时给明确提示 |
| `tools/train_baseline.py` | **新建**：训任意 (数据集 × 模型) 组合的基线 |

**回归验证已通过**：`cifar10 + resnet18` 精确复现 **87.16%**，BN 折叠后剩余 0 层、
精度不变。这说明参数化没有破坏原有路径。

## 四、MobileNetV2 的兼容性预检（已实测）

| 检查项 | 结果 |
|---|---|
| 前向形状 | (4,3,32,32) → (4,10) ✓ |
| Conv2d / BN 层数 | 52 / 52 |
| **BN 折叠前后最大差异** | **2.7e-16**（浮点极限，数学等价）|
| 折叠后剩余 BN | 0 |
| `fold_all_bn` 是否认 ResNet 结构 | **不认**——它是递归通用实现，按"相邻 (Conv2d, BatchNorm2d)"配对 |

**结论：MobileNetV2 可以直接跑，不需要改折叠逻辑。**

## 五、为什么 MobileNetV2 比 CIFAR-100 更值得先做

| | CIFAR-100 + ResNet-18 | **CIFAR-10 + MobileNetV2** |
|---|---|---|
| 需要新数据 | 是（169MB，校园网 45 KB/s ≈ **1 小时**）| **否，数据已在本地** |
| 对现有结论的挑战 | 弱（模型没变，只是数据变了） | **强**（17 个 depthwise conv 是量化重灾区）|
| 训练成本 | 11.18M 参数 | **2.24M 参数（1/5）** |
| 能验证什么 | 结论跨数据集是否成立 | **结论跨模型架构是否成立** |

**关键点**：现有结论里最脆弱的一条是
> **"conv1 是唯一的硬骨头，它一个层抵得上其余十九层"**

这条本质是"首层敏感"。但 MobileNetV2 有 17 个 depthwise conv，
**如果换模型后这条不成立，它就必须被修正**——而修正本身就是论文价值。
