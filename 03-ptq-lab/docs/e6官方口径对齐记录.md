## 一、检查结论：5 个偏差，1 个框架级限制

| # | 项 | 旧版 | 官方 | 严重度 |
|---|---|---|---|---|
| 1 | **迭代步数** | `iters=300` | **20000**（BRECQ默认）／15000（AIMET <8bit） | 🔴 P0 |
| 2 | **β 温度** | 固定 `1.2 / 0.1` | **20 → 2，cosine 退火** | 🔴 P0 |
| 3 | **正则 warm start** | 无 | **前 20% 迭代完全不施加正则** | 🔴 P0 |
| 4 | **重建 loss** | MSE `.mean()` | **L_p(p=2.4) `.sum(dim=1).mean()`** | 🔴 P0 |
| 5 | **asymmetric loss** | 否（FP 分支吃干净输入） | **是**（两分支都吃已量化的 x̂） | 🟠 P1 |
| 6 | **scale 粒度** | per-channel | **per-tensor** | 🟡 P2 |
| 7 | **学习率** | 固定 2e-3 | cosine 衰减 | 🟡 P2 |
| 8 | **末层 lm_head** | 被 `isinstance(Conv2d)` 筛掉 | 官方全网量化含末层 | ⚠️ 框架限制 |

**旧版为什么只有 +1.48%，官方 ResNet18 W4 能救回 44 个百分点？**
三个原因叠加：步数少 66 倍、末层完全没优化、β 固定低温导致 h 一开始就被压死无法探索。

### 已经正确的部分（保留）
- ✅ **λ = 0.01**（两个官方实现都是这个值）
- ✅ **batch = 32**
- ✅ **α 解析初始化**（旧版 `logit((frac+0.1)/1.2)` 与官方 `-log((zeta-gamma)/(rest-gamma)-1)` 等价）
- ✅ **hard rounding 导出**（`h > 0.5`）
- ✅ **Adam 优化器**
- ✅ **loss 的形式**（`recon + λ·reg`）

## 二、两处与官方**不可比**（不是 bug，是平台框架的既成事实）

这两条**必须在论文/报告里声明**，否则会被质疑：

### ① `lm_head` 从不参与量化

`src/model.py` 的 `build_quant_model` 只包装 `nn.Conv2d`：
```python
for nm, mod in list(m.named_modules()):
    if not isinstance(mod, nn.Conv2d):
        continue
```
ResNet-18 的 `lm_head` 是 `nn.Linear`，**永远不会被量化**。官方 AdaRound 是全网量化含末层。

**影响**：本实验的 AdaRound 提升会**偏乐观**（少优化了一层）。
**写法**：不能写"对齐 AdaRound 官方"，要写"全网量化 Conv2d 层，lm_head 保持 FP32"。

### ② scale 粒度

官方 AdaRound 用 **per-tensor（per-layer scale）**。旧版用 per-channel，精度天然更高。
现默认 per-tensor（对齐官方），`--per-channel` 可切回。

## 三、重写后的关键实现（官方口径）

### β cosine 退火（对齐 BRECQ `LinearTempDecay`）
```
if t < rel_start_decay × t_max:  return start_b          # 20
rel_t = (t − start_decay) / (t_max − start_decay)
return end_b + (start_b − end_b) × max(0, 1 − rel_t)     # → 2
```
`rel_start_decay = warmup = 0.2`

### 正则项的 warm start
```python
if it < iters × 0.2:
    loss = rec                # 前 20% 完全不施加正则
else:
    b = temp_decay(it + 1)
    round_loss = (1 − ((h − 0.5).abs() × 2).pow(b)).sum()
    loss = rec + 0.01 × round_loss
```

### 重建 loss（广义 L_p）
```python
rec = (out_q − ref).abs().pow(2.4).sum(dim=1).mean()
```
不是 `F.mse_loss()` —— 梯度尺度不同。

### asymmetric loss 的实现方式
```python
# 先建 W4A8 量化模型，用它跑前向、hook 采到的就是「误差已传播过」的 x̂
m_partial = M.build_quant_model(m, w_bits=4, a_bits=8, a_s, a_z)
x_hat = collect_real_activations(m_partial, batch_size=32)
# 重建时 FP 分支与量化分支都吃 x̂
ref = c2d(w)     # 用 x̂ 算FP32 输出
```

### α 解析初始化
```python
alpha = −log((zeta − gamma) / (rest − gamma) − 1)   # gamma=-0.1, zeta=1.1
# 使初始 h(α) 精确复现 RTN
```

## 四、踩到的两个坑（已修）

### 坑 1：`collect_real_activations` 采不到量化模型的层
`QuantConv2d` 继承 `nn.Module`，**不是 `nn.Conv2d`**。在量化模型上 hook 时
`isinstance(mod, nn.Conv2d)` 一层都匹配不到 → `已采集 0 层`。

**修**：`isinstance(mod, (nn.Conv2d, QuantConv2d))`。

### 坑 2：提前 return 导致永远返回空
我加的 `if not store: return store` 放在了 hook **触发之前**，
此时 `store` 还是空的，所以每次都提前返回。**结果是"0 层优化"，
但最终精度看起来正常（87.07%，因为 `w_bits=0` 等于没量化）—— 极具欺骗性。**

**修**：删掉该判断。

> ⚠️ **这个坑值得记住**：冒烟测试时"精度看起来正常"反而掩盖了 bug。
> 判断改动是否生效，**要看"优化了多少层"，不要只看最终精度**。

## 五、⭐ 核心发现：2×2 对照表（本轮最有价值的产出）

修完之后跑出一个完整的 2×2 对照。**这是理解 AdaRound 真正价值的钥匙**：

| scale 粒度 | RTN W4A8 | AdaRound W4A8 | **AdaRound 提升** |
|---|---|---|---|
| **per-tensor**（AdaRound 官方口径） | **77.81%** | **86.54%** | **+8.73 pp** ⭐ |
| **per-channel**（本平台 e2/e5 口径） | **85.28%** | **86.89%** | **+1.61 pp** |

FP32 基线 87.16%（ResNet-18 / CIFAR-10 / W4A8）

> 全部为 iters=20000 实测。per-channel 那一行的 AdaRound 旧版（iters=300）只有 86.76%（+1.48pp），
> 官方步数下升到 86.89%（+1.61pp）——**步数修正带来 +0.13pp，符合预期但幅度不大**。

### ⭐ 这张表说明什么

**① AdaRound 真正的价值是在「粗粒度 scale」下救回精度。**

看 per-tensor 那一行：RTN 只有 77.81%（掉 9.35 pp），AdaRound 救回 86.54%（几乎回到 FP32）。
这正好对应论文里InceptionV3 的现象——**RTN 在 4bit 下崩到 1.67%，AdaRound 恢复到 75.76%**。
说明 AdaRound 解决的是「scale 粗导致大量权重落在错误档位」的问题。

**② 为什么你原来的 e6 只看到 +1.48%？**

因为你的平台用 **per-channel**，RTN 基线已经有 85.28%（只掉 1.88 pp）——
**留给 AdaRound 的空间本来就小**。所以 +1.48% 不是 AdaRound 不行，
而是「per-channel 已经把AdaRound 能救的那部分救掉了」。

**③ 这反过来证明你 e2 的结论是稳的。**

e2 的「权重 8→4 掉 1.75%」用的是 per-channel。
如果换per-tensor，掉点会变成 9.35 pp —— **差了 5 倍多**。
→ **scale 粒度对量化精度的影响，比位宽本身还大。** 这是一个值得写进论文的观察。

### ⚠️ 报告/论文里的正确写法

**不要写**："AdaRound 带来 +1.26% 提升"（这是 per-tensor AdaRound 比 per-channel RTN，口径错配）

**应该写**两种之一：
- **对齐官方**：RTN 77.81% → AdaRound 86.54%（+8.73 pp），per-tensor
- **对齐平台口径**：RTN 85.28% → AdaRound 86.76%（+1.48 pp），per-channel

**并且必须声明 lm_head 不参与量化**（见第二节 ①）。

## 九、给论文的建议写法

### 主表放哪组？
**建议放 per-tensor 那组**（+8.73 pp），理由：
1. 对齐 AdaRound 官方口径，能直接和论文/其他工作对比
2. 数字有说服力（RTN 掉 9.35pp → AdaRound 几乎救回）
3. per-channel 那组留着做「我们平台默认口径下的对照」

### 必须写的口径声明
>本实验对全部 `nn.Conv2d` 做量化（20 层），`lm_head`（`nn.Linear`）保持 FP32；
> AdaRound 超参对齐 AIMET/BRECQ 默认（iters=20000、λ=0.01、β=20→2 cosine、
> 前 20% warm start、batch=32、L_p p=2.4），但重建采用**逐层非对称 loss**
> （单层重建而非 block 重建），故与官方 BRECQ 的 block 级重建仍有差异。

### 一个可以写进论文的观察
> 同为W4A8，per-tensor scale 的 RTN 掉 9.35 个百分点，而 per-channel 仅掉 1.88 个——
> **scale 粒度带来的差异（7.5 pp）比把位宽从 8 降到 4 带来的差异（1.88 pp）大得多**。
> 这说明 PTQ 的误差主要来源不是位宽本身，而是「有限档位如何分配给真实数据」。
