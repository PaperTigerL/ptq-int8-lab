# ⚠️ 重要修正：e7 的混合精度位宽口径不一致（2026-10-17 发现并修复）

## 问题

四组 e7 跑完后对比时发现，**混合精度的平均位宽口径不一致**：

| 组合 | 旧 e7 混合精度位宽 | 是否合理 |
|---|---|---|
| CIFAR-10 ResNet-18 | 4.31 | ✓ |
| CIFAR-10 MobileNetV2 | 4.06 | ✓ |
| **CIFAR-100 ResNet-18** | **6.28** | ⛔ **几乎没压缩** |
| CIFAR-100 MobileNetV2 | 4.07 | ✓ |

**CIFAR-100 + ResNet-18 的混合精度用了 6.28 bit**，而其他三组都在 4.1–4.3。
**它的"混合精度收益 +2.66 pp"是花了近 8 bit 的代价换来的，与其他三组不可比。**

## 根因

```python
# 旧版 e7_combo.py
KEEP = 10          # 保 8bit 的层数（e5 实测最优）
```

`KEEP=10` 是 e5 在 **CIFAR-10 + ResNet-18** 上测出的最优值。
但 `avg_bits` 是**按参数量加权**的，不是按层数。

CIFAR-100 的敏感度分布不同：同样保护 10 层，**被保护的层占了绝大部分参数量**，
于是平均位宽飙到 6.28。

**而 `config.MIXED_MAX_AVG_BITS = 5.0` 这个约束，此前在 e7 里完全没有被使用。**

## 从 e5 数据看自动选 KEEP 的效果

| 组合 | 旧 KEEP=10 | 自动选（≤5.0 约束下最多层） | 变化 |
|---|---|---|---|
| CIFAR-10 ResNet-18 | KEEP=10 → 4.31 | KEEP=10 → 4.31 | 不变 |
| CIFAR-10 MobileNetV2 | KEEP=10 → 4.06 | **KEEP=20 → 4.75** | 精度更高（83.40 vs 82.91） |
| CIFAR-100 ResNet-18 | KEEP=10 → **6.28** ⛔ | **KEEP=4 → 4.47** | 回归合理压缩 |
| CIFAR-100 MobileNetV2 | KEEP=10 → 4.07 | **KEEP=20 → 4.62** | 精度更高（55.02 vs 54.20） |

## 修复

`e7_combo.py` 新增 `pick_keep()`：
**在 `MIXED_MAX_AVG_BITS` 约束下，选能保住的最多 8bit 层数。**

这样四组之间位宽口径统一，混合精度收益才可比。

## 影响

**三个组合的 e7 需要重跑**（KEEP 会变）：

| 组合 | 旧 e7 数据 | 状态 |
|---|---|---|
| CIFAR-100 ResNet-18 | KEEP=10 → 6.28 ⛔ | 🔄 重跑中 |
| CIFAR-10 ResNet-18 | KEEP=10 → 4.31 | 不变，但需确认 |
| CIFAR-10 MobileNetV2 | KEEP=10 → 4.06 | 需重跑（KEEP→20） |
| CIFAR-100 MobileNetV2 | KEEP=10 → 4.07 | 需重跑（KEEP→20） |

**⚠️ 在此之前，文档里所有涉及 e7 混合精度的数字都需重新核对。**

## 教训

> **"按层数"和"按参数量"是两回事。**
> 我此前默认"保护 10 层"在所有组合上都等价于"保护一小部分参数量"，
> 但 `avg_bits` 是按参数量加权的——**敏感度分布一变，层数口径就失效**。
>
> **判据：任何"保护 N 层"的策略，都必须同时检查平均位宽是否仍在预算内。**
> 否则某几个组合会悄悄失去压缩意义，而你还以为在跟别人比同一件事。
